# Clinical score and statistical analysis

Before the trial, use `gpc_hierarchy()` to choose the clinical rule. The first death settles the pair under every supported rule. If both patients are alive at the comparison time, favor fewer admissions; with equal positive counts, favor a later last admission. Equal dates tie. To favor a later first admission instead, set `admission_time = "first"`; to stop at count, set `admission_time = "none"`. With no admissions in either patient, the timing tier ties. If comparing admission time without count, one patient with no admissions wins against one admitted even exactly at the cutoff.

For a biomarker, compare the latest observed values only if preceding tiers tie. A clinical cutoff and a minimum difference are distinct rules. With `biomarker_threshold = 10`, two values of 4 and 8 are in the same category; with `biomarker_margin = 0` they are distinct. The clinical cutoff uses strict `>`; a value equal to the cutoff is in the lower category. A difference equal to a pairwise margin does not decide the pair. Choose lower (default) or higher as favorable. A missing necessary value defers the computation; no marker is used unless specified.

## What depends on the rule

The clinical provider receives the cutoff and histories of the two living, observed patients. It returns +1, -1 or 0 from the treatment patient's perspective. The inference routines use patient score totals and their distribution over observed comparison times. It forms win and loss indicators, weights, patient projections and the influence of the estimated censoring probabilities exactly as for the default rule. Changing the rule changes the clinical estimand and the resulting scores but does not change the uncertainty formula or stopping procedure. The state-based net win time uses its separately prescribed state order.

The shared-window test uses the shorter observed follow-up of the pair. IPCW requires observation through the first death or the horizon, whichever comes first. These window and ascertainment rules — and the comparison settled by the first death, including a tie on simultaneous deaths — remain outside the customizable provider. A custom rule cannot reverse a death decision.

## Internal provider

The general pair scorer constructs `.pair_score_provider(patients, events, ti, ci, ordered_ends, rule, channels, restricted)` once per look from the validated patient records. It returns a function `score_alive(r, i, j, at)`: `r` indexes the nondecreasing sequence of treatment cutoffs, `i` indexes that treatment patient in its arm, `j` are the indices of the living, ascertained control partners and `at` is the cutoff for each pair. The provider returns an aligned vector of signed scores. Ranks may be skipped and must not run backward. This interface requires no probability weights, censoring estimates or treatment-effect specification.

When the general pair scorer evaluates built-in tiers, `.pair_events()` sorts observed records once. While treatment cutoffs advance, the provider updates the control admission count, first or last admission time if required, and last marker if required. Control records never extend beyond the control's observed end. Treatment records are indexed separately at each actual pair cutoff. Computation uses linear storage in patients plus records, including at most one arm-sized vector of scores at a time. For restricted IPCW with rankable ordered clinical tiers, the package instead groups deaths by observation time and ranks the patients observed alive at the horizon. See `pair-influences.md` for the calculation.

A custom comparator receives the two named clinical histories in chronological order through the pair-specific cutoff. Where selected, the `admissions` (times) and `biomarker` (time/value data frame) aliases reproduce their native counterparts. It receives neither arm labels nor future follow-up or future events. It replaces the lower tiers, and must be prespecified, deterministic, antisymmetric and defined for the histories it uses. Its scalar return is checked, but its clinical meaning, use of external data and antisymmetry are the analyst's responsibility. Access to all available history through the cutoff makes a general callback more expensive per pair than the built-in rules. It cannot change ascertainment or the weight-fitting procedure.

Old saved monitoring plans without a hierarchy retain their original survival/count rule and optional marker; the new last-admission default applies when constructing a new plan. Reproduce an old new-from-source design explicitly with `gpc_hierarchy(admission_time = "none")`.

## Order endpoints from the study

`gpc_hierarchy(endpoints = list(relapse = gpc_endpoint("relapse", "count"), fatigue = gpc_endpoint("fatigue", "value")))` compares survival, then relapse counts, then the latest fatigue score. Reversing the list reverses those two lower priorities. Supply the event table under `events = list(relapse = ...)` and the measurement table under `measurements = list(fatigue = ...)`. A known event channel without observations is an empty id/time table. Omitting that channel entirely is an input error. A required value tier without a measurement by the cutoff is unascertained and defers the look.

`gpc_endpoint(channel, type, direction, threshold, margin)` builds a signed tier using count, first time, last time or latest measured value. A clinical threshold is available for values only; a minimum pairwise difference is measured in the units of the chosen summary. For a first/last time, patients without the event are later than all patients with an event; no-event versus no-event ties. The default counts/timing/marker hierarchy remains available as a preset.

An arbitrary signed function can occupy any named tier or define all lower tiers through `compare`. It receives `h$events[[name]]`, a sorted vector of times, and `h$measurements[[name]]`, a sorted time/value data frame, individually truncated for each pair. Never consult later records, arm labels or the rest of the trial. Swapping the histories must reverse its sign. Values can represent a prespecified binary, ordinal or continuous measurement; any numeric coding of a clinical category must have the intended interpretation. Derived summaries, including patient-specific trajectories, can be calculated inside a tier. Do not invent a value for an unobserved endpoint. In custom code, exact lookup of an undeclared channel fails; a declared empty channel is available. The older admissions/biomarker aliases are supplied only for selected channels or the corresponding native input columns. Prepared named data should use the original channel names.

|---|---|

No observed pair is decided by reading a later endpoint after an earlier tier settles it. Validation of the data schema and reporting times precedes clinical scoring. More complex callback rules may take more computation than declarative or preset rules; the uncertainty and monitoring algorithms require no changes.
